## 3. Creating a skill (when I ask, or when a workflow repeats 2+ times)
1. Overlap: read the descriptions of all existing skills and agents. Extend an existing one rather than adding a sibling.
2. Scope: write 3 real prompts the skill must handle and 1 it must not, plus what goes wrong today without it. Ask me if unclear.
3. Mine the codebase with parallel `explorer` calls, one question each, each needing `path:line` evidence:
   - Commands: package manifest scripts, Makefile/justfile, CI config. What do they run and write?
   - Data and formats: where inputs and outputs live. Read one real example of each format.
   - Reuse: helpers, base classes, page objects, fixtures and utilities the skill must point to, not reinvent.
   - Source of truth: README, docs/, specs, rules files, existing CLAUDE.md.
   - Gotchas: TODO/FIXME/HACK comments, bug notes, recent `git log` hot spots, failing-test history.
   - Forbidden: `.claude/settings.json` deny list and hooks. The skill must never instruct a denied action.
   Keep the findings in a scratch knowledge file (fact → `path:line`). Only evidenced facts go into the skill.
4. Write `.claude/skills/<name>/SKILL.md`:
   - `name` = folder name, lowercase-hyphen, verb-first (e.g. `triaging-test-failures`).
   - `description` starts "Use when…", lists triggers and keywords only, never the workflow (Claude follows a summarised workflow and skips the body). Third person, ≤1024 chars.
   - Set `model` / `effort` frontmatter only with a reason.
   - Body under 500 words: core principle (1-2 sentences), then a quick-reference table of real commands and repo-relative paths, then numbered steps for the judgment parts, then a common-mistakes table built from the gotchas.
   - Move reference material over ~100 lines into a supporting file. Reference other skills by name, never with `@` links. Turn anything regex-checkable into a script instead of prose.
5. Verify, and report the result honestly:
   - Every backtick path exists, every script/command named exists in the manifest, every link resolves, every skill/agent named exists, and frontmatter values are valid.
   - Each factual claim is re-checked against code by `explorer`.
   - Offer, because it costs subagents: run the 3 scoped prompts against a fresh subagent and check it follows the skill.

## 4. Auditing skills (when I ask, after big code changes, or when a skill misled you)

2. Facts: list checkable claims (commands, names, enums, formats, numbers), verify each with `explorer`, and mark it correct / stale / wrong / unverifiable.
3. Coverage: files changed since the skill was last edited (`find <src dirs> -newer <SKILL.md>` or `git log --since`), plus new scripts, fields or recurring failures the skill doesn't mention.
4. Triggers: 3 realistic prompts per skill. Exactly one description should match each. Two matches means overlap; none means weak triggers.
