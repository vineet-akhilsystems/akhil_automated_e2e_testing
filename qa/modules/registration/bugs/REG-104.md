# Bug Report: REG-104 — Unescaped Regex in Top-Bar Patient Search Causes HTTP 500 on Special Characters (`(`)

- **Case ID:** `REG-104`
- **Module:** Patient Registration — Top-Bar Global Patient Search (`POST /patient-registration/get-all-patient-details`)
- **Severity:** High (Backend Unhandled Exception / HTTP 500)
- **Priority:** P1
- **Environment:** `https://demo.augastam.com/registration` / `https://demo-backend.augastam.com` (Build `2.0.66`)
- **Status:** Confirmed Product Bug

---

## 1. Summary
Typing a search query containing regex metacharacters such as an opening parenthesis `(` (e.g., `"Agent("`) into the top-bar patient search input causes the backend endpoint `POST /patient-registration/get-all-patient-details` to crash with **HTTP 500 Internal Server Error**. The backend passes the raw user input string directly into `new RegExp(searchText, 'i')` without escaping special regex characters.

---

## 2. Steps to Reproduce
1. Open Patient Registration (`/registration/1101f999-7c91-4ba5-a52b-a80d728c588e`).
2. Click the top-bar search input (`Search by Patient Name, UHID, Mobile Number`).
3. Type `Agent(` and wait ~400ms for the debounced search API call.
4. Inspect the Network response for `POST https://demo-backend.augastam.com/patient-registration/get-all-patient-details`.

---

## 3. Expected vs. Actual Result
- **Expected:**
  - Special characters in the search box (`(`, `)`, `[`, `]`, `+`, `*`, `?`, `\`) are treated as literal characters.
  - The API returns `HTTP 200` (or `201`) with matching records or an empty list `[]`.
- **Actual:**
  - The API returns **HTTP 500 Internal Server Error** (observed twice per search due to retry/effect).
  - The UI dropdown displays `"0 records found"` while masking the server crash.

---

## 4. Root Cause Analysis (Hypothesis with Code Reference)
- **File:** `akhil_systems_backend/src/patient-registration/patient-registration.controller.ts:4900-4901`
- **Code Logic:**
  ```typescript
  // patient-registration.controller.ts:4900-4901
  const searchText = (prefix || '').trim();
  const regexString = searchText ? new RegExp(searchText, 'i') : null;
  ```
- **Why It Fails:**
  - When `prefix` is `"Agent("`, `new RegExp("Agent(", "i")` throws:
    `SyntaxError: Invalid regular expression: /Agent(/i: Unterminated group`
  - The same vulnerability affects any search containing `+` (e.g. blood group `"O+"` or country code `"+91"` at start), `[`, `(`, `)`, or trailing `\`.
  - Note: A similar unescaped `new RegExp(searchText, 'i')` also exists at `patient-registration.controller.ts:5181`.

---

## 5. Recommended Fix
Escape all regular expression metacharacters before constructing the `RegExp` instance:

```typescript
const escapeRegExp = (str: string) => str.replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
const searchText = (prefix || '').trim();
const regexString = searchText ? new RegExp(escapeRegExp(searchText), 'i') : null;
```
