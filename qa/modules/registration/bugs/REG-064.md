# Bug Report: REG-064 — Reverse PIN Lookup (`State` + `District` + `Area` -> `Pin Code`) Fails or Flags False Mismatch

- **Case ID:** `REG-064`
- **Module:** Patient Registration — Address Details (`PinCodeField` / `pincodeAutofill` / `pincode-lookup`)
- **Severity:** Medium-High (Broken Reverse Autofill & False Validation Warning)
- **Priority:** P2
- **Environment:** `https://demo.augastam.com/registration` (Build `2.0.66`, Tenant: `Miracle HIS Demo`)
- **Status:** Confirmed Product Bug

---

## 1. Summary
When a user leaves **Pin Code** empty and selects **State** (`DELHI`), **District** (`NEW DELHI`), and **Area** (`F F C Okhla`), the reverse PIN lookup either:
1. Leaves **Pin Code** empty during standard sequential selection (`actualPinCode: ""`), or
2. When the fallback lookup (`State` + `Area`) resolves PIN `110020`, immediately displays the red warning **"Address details don't match the entered PIN code"** (`REG-064.png`) because the dropdown hierarchy (`parent-lookup`) maps `F F C Okhla` under District `NEW DELHI`, whereas the backend Pincode Directory (`pincode-lookup`) maps PIN `110020` (`F F C Okhla`) under District `SOUTH DELHI`.

---

## 2. Steps to Reproduce
1. Open Patient Registration (`/registration/1101f999-7c91-4ba5-a52b-a80d728c588e`).
2. Scroll to **Address Details** (Current Address tab) and leave **Pin Code** blank.
3. Select **Country** = `INDIA` (default), **State** = `DELHI`.
4. Select **District** = `NEW DELHI` (and **City** = `NEW DELHI`).
5. Select **Area** = `F F C Okhla`.
6. Observe the **Pin Code** field and the validation banner below it.

---

## 3. Expected vs. Actual Result
- **Expected:**
  - Selecting `State = DELHI`, `District = NEW DELHI`, `Area = F F C Okhla` cleanly populates **Pin Code** = `110020` without any mismatch error.
- **Actual:**
  - First reverse lookup query `POST /reference-lookup/pincode-lookup` with `{ state: "DELHI", district: "NEW DELHI", area: "F F C Okhla" }` returns `0` matches (`data: []`) because the Pincode Directory stores `110020` under district `SOUTH DELHI`.
  - Second fallback query `{ state: "DELHI", area: "F F C Okhla" }` returns `110020` (`district: "SOUTH DELHI"`), which then triggers `lookup("110020", true)`.
  - `addressMismatchesPin` compares the user's selected District (`NEW DELHI`) against the PIN directory's District (`SOUTH DELHI`) and displays **"Address details don't match the entered PIN code"** (`test-results/.../REG-064.png`), or in fast execution the 400ms timer + sequential 2-request chain fails to populate `pin_code` before interaction continues.

---

## 4. Root Cause Analysis (Hypothesis with Code Reference)
1. **Data Source / Config Mismatch (`webpart_latest_version__3e2a2f1c-ca60-4b8a-bea9-91e3c79eab86.json` & `pincode-lookup.util.ts:99-117`):**
   - In the `Address Details` webpart configuration, both `City` (`id: 35`) and `District` (`id: 37`) are configured with `"multiLevelDataSource": "state"`. When `State = DELHI` is chosen, `District` is populated from the master `parent-lookup` table (`NEW DELHI`), whereas `POST /reference-lookup/pincode-lookup` queries the India Post Pincode Directory where `110020` (`F F C Okhla`) has `District = SOUTH DELHI`.
2. **Area Change Ignored When `pinSource === 'system'` (`custom-form-builder/src/components/registration/builder/PinCodeField.jsx:161-170`):**
   ```javascript
   // PinCodeField.jsx:161-170
   } else if (column === cols.district || column === cols.city) {
     // Keep state
   } else {
     return; // <-- When column === cols.area and pinSource === 'system', early-returns without updating!
   }
   ```
3. **Self-Contradicting Reverse Lookup Follow-up (`PinCodeField.jsx:335-361`):**
   - When `reverseLookupAttempts` falls back from `{state, district, area}` to `{state, area}` (`pincodeAutofill.js:167-169`) and finds PIN `110020`, `PinCodeField.jsx:350` calls `lookup("110020", true)`. That forward lookup compares `district` (`SOUTH DELHI`) against the manual `district` (`NEW DELHI`) and raises `mismatchWarning = true` (`"Address details don't match the entered PIN code"`).

---

## 5. Recommended Fix
1. In `PinCodeField.jsx:347-353`, when reverse lookup succeeds via the `{ state, area }` fallback, either update the `district`/`city` fields from the matched PIN record (if not locked) or do not flag a mismatch on `district` when the PIN was auto-derived by the system from `state + area`.
2. In `PinCodeField.jsx:167`, handle `column === cols.area` so changing the Area re-evaluates/updates the system-derived PIN code instead of returning early.
3. Align the `Address Details` webpart `District` / `Area` master data with the Pincode Directory (`SOUTH DELHI` vs `NEW DELHI`).
