# Bug Report: REG-033 / REG-085 / REG-069 — Form Validation & Config Discrepancies (Blur-Only Validation, Missing Name-Split Flags, Premature Errors on Type Switch, Hidden Tab Block)

- **Case IDs:** `REG-033`, `REG-085`, `REG-069` (plus validation enforcement gaps `REG-025`, `REG-026`, `REG-027`, `REG-040`, `REG-050`, `REG-151`, `REG-160`, `REG-191`, `REG-192`)
- **Module:** Patient Registration — Form Validation & Webpart Configuration (`RegistrationPreview.jsx`, `RegistrationWebpartPreview.jsx`, `WebpartUtils.js`)
- **Severity:** High (Invalid Clinical/Demographic Data Persisted to DB & UX Defects)
- **Priority:** P1
- **Environment:** `https://demo.augastam.com/registration` (Build `2.0.66`, Tenant: `Miracle HIS Demo`)
- **Status:** Confirmed Product & Configuration Bugs

---

## 1. Summary of Issues

### Issue A (`REG-085`): Switching Registration Type Triggers Premature `"This field is required."` Errors
- **Observed Behavior:** Switching the **Registration Type** dropdown (e.g., from `Normal Registration` to `Emergency Registration` or `New Born Registration`) before typing anything into the form immediately displays red `"This field is required."` errors under **First Name*** and **Last Name*** (captured in walkthrough frames `pr_02.png`, `pr_06.png`, `pr_07.png`, `pr_09.png`).
- **Root Cause:** Changing Registration Type re-evaluates/blurs active webpart fields before user interaction, triggering required-field error states prematurely.

### Issue B (`REG-033`): Full Name Auto-Splitting (`"First Middle Last"`) Does Not Run Due to Missing Webpart Attributes
- **Observed Behavior:** Typing `"Agent Kumar Testing"` into **First Name** and blurring leaves the entire string `"Agent Kumar Testing"` in **First Name** and leaves **Middle Name** and **Last Name** empty.
- **Root Cause (`RegistrationWebpartPreview.jsx:758-800` & `webpart_latest_version__5b5bc4c1-bafb-4432-b3f2-caaa0a4c2e7f.json`):**
  - `RegistrationWebpartPreview.jsx:758-800` implements full-name splitting on blur, **but only when** the fields have `attributes.isFirstName: true`, `attributes.isMiddleName: true`, and `attributes.isLastName: true`.
  - In the live `Basic Information` webpart JSON (`5b5bc4c1-bafb-4432-b3f2-caaa0a4c2e7f`), `first_name` (`id: 2`), `middle_name` (`id: 3`), and `last_name` (`id: 4`) do **not** have `isFirstName` / `isMiddleName` / `isLastName` set (instead, `Mobile No` `id: 1` has `"isFirstName": false, "isMiddleName": false, "isLastName": false`).

### Issue C (`REG-069`): Hidden "Permanent Address" Tab Blocks Save With `"Please fill the required field: Pin Code (Permanent Address)"`
- **Observed Behavior:** When the user fills all required fields on the visible **Current Address** tab (`Pin Code`, `State`, `District`, `City`, `Area`) and clicks **Save** without ticking `"Mark current address as permanent"`, Save is blocked with the error toast:
  `"Please fill the required field: Pin Code (Permanent Address)"`.
- **UX Impact:** Because the **Permanent Address** tab is hidden behind a secondary tab header, users have no visual indication on the active tab why **Pin Code** is being reported as missing when Current Address Pin Code is already filled.

### Issue D (Save-Time Validation Bypass): Blur-Only Field Validation Allows Invalid Emails, Short Phones, Future DOBs, and 30-Year-Old "New Borns" to Save
- **Observed Behavior:** Clicking **Save** persists records with:
  - Invalid email formats (`agent@` -> UHID `ASNR0000000431`, `REG-050`; `agent testing@example.com` -> UHID `ASNR0000000450`, `REG-151`)
  - 5-digit WhatsApp numbers (`98765` -> UHID `ASNR0000000424`, `REG-026`) and 3-digit Emergency Contact numbers (`123` -> UHID `ASNR0000000425`, `REG-027`)
  - Future DOB (`01/01/2030` -> UHID `ASNR0000000428`, `REG-040`) and DOB in year `1900` / Age `150` (`REG-044`, `REG-045`)
  - **New Born** registrations with a 30-year-old DOB (`15/08/1996` -> UHID `ASNBR240000000009`, `REG-192`) or a non-existent Mother's UHID (`ASNR9999999999` -> UHID `ASNBR240000000008`, `REG-191`).
- **Root Cause (`RegistrationPreview.jsx:2882-2925` & `WebpartUtils.js`):**
  - `validateRequiredFields` in `RegistrationPreview.jsx:2882-2925` **only** checks whether `required` fields are non-empty (`isValueEmpty`). It never invokes `validateFieldValue()` from `WebpartUtils.js` or checks existing `validationErrors` state before calling `createPatientRegistration`!
  - Furthermore, in the live `Basic Information` webpart config, `Email` (`id: 7`) has `"regex": ""` and `WhatsApp No.` (`id: 14`) has `"minLength": ""`.

---

## 2. Recommended Fixes
1. **Enforce Field Validation on Save (`RegistrationPreview.jsx:2882`):** Run `validateFieldValue` across all populated fields during `handleSave` and block submission if any field fails regex, `minLength`/`maxLength`, or date-range validation.
2. **DOB & New Born Clinical Bounds (`DateField.jsx` & `patient-registration.controller.ts`):** Reject future dates (`DOB > today`) and enforce a maximum age threshold for `New Born Registration`.
3. **Webpart Config (`Basic Information`):** Set `isFirstName: true`, `isMiddleName: true`, `isLastName: true` on the respective name fields, add `minLength: "10"` to `WhatsApp No.` and Emergency `MobileNumber`, and configure standard email validation on `Email`.
