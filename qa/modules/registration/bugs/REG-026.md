# Bug / Requirement Gap Report: REG-025 / REG-026 / REG-027 / REG-160 — Invalid Phone Numbers (5-Digit WhatsApp, 3-Digit Emergency Mobile, Same-as-Patient Emergency Mobile, `9999999999`) Are Saved

- **Case IDs:** `REG-025`, `REG-026`, `REG-027`, `REG-160`
- **Module:** Patient Registration — Phone Validation (`Basic Information` & `Additional Details -> Emergency Info`)
- **Severity:** Medium-High (Unusable Emergency & Patient Contact Numbers Persisted)
- **Priority:** P2
- **Environment:** `https://demo.augastam.com/registration` (Build `2.0.66`, Tenant: `Miracle HIS Demo`)
- **Status:** Confirmed Validation & Config Defect (Verified Live with Created UHIDs)

---

## 1. Summary
While primary **Mobile No.** enforces a 10-digit Indian mobile rule via `phoneRules.js` (`REG-020` and `REG-220` properly block 9-digit primary mobile numbers), secondary phone fields and cross-field phone checks are not enforced on Save:
1. **`REG-026` (5-Digit WhatsApp Number Saved):** Entering `98765` in **WhatsApp No.** saves and creates **UHID `ASNR0000000424`**.
2. **`REG-027` (3-Digit Emergency Contact Mobile Saved):** Entering `123` in **Emergency Info -> Mobile Number** saves and creates **UHID `ASNR0000000425`**.
3. **`REG-160` (Emergency Contact Mobile Same as Patient Mobile Saved):** Entering the patient's own mobile number (`9440425000`) as the Emergency Contact Mobile saves without warning and creates **UHID `ASNR0000000442`**.
4. **`REG-025` (Repeating-Digit Mobile `9999999999` Saved):** Entering `9999999999` in **Mobile No.** saves and creates **UHID `ASNR0000000423`**.

---

## 2. Root Cause & Code Logic
1. **Primary Phone Check Only Validates Primary Mobile (`RegistrationPreview.jsx` & `phoneRules.js`):**
   - On Save, phone length/country validation only checks the primary `mobile` field, ignoring `whatsapp_number` and the `Emergency Info` webpart's `MobileNumber` field unless they are marked required or blurred with a country phone rule that blocks Save.
2. **Blur-Only Validation Not Checked on Save (`RegistrationPreview.jsx:2882-2925`):**
   - Even if `Emergency Info -> MobileNumber` or `WhatsApp No.` shows an inline error on blur, `handleSave()` does not check `validationErrors` before calling `POST /patient-registration/create`.
3. **No Cross-Field Check (`mobile !== emergency_mobile`) or Repeating-Digit Rule:**
   - Neither frontend nor backend checks whether `emergency_mobile === mobile` or rejects dummy repeating digits (`^(\d)\1{9}$`).

---

## 3. Recommended Fix
1. Apply the country-aware phone validator (`validatePhoneValue` in `phoneRules.js`) to all phone-type fields (`Mobile No.`, `WhatsApp No.`, `Emergency Mobile Number`) inside `handleSave()` whenever they are non-empty.
2. Add a cross-field validation warning/block when `emergency_mobile === mobile` and reject dummy 10-same-digit numbers (`^(\d)\1{9}$`).
