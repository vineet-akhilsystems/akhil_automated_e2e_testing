# Bug Report: REG-090 — Backend Returns `{statusCode: 409 | 500}` Inside HTTP 200; Frontend `api.js` Only Checks `statusCode === 400`

- **Case ID:** `REG-090`
- **Module:** Patient Registration — Create & Update API Error Handling (`api.js` & `patient-registration.controller.ts`)
- **Severity:** High (API Contract Bug / `[object Object]` UHID Navigation Risk)
- **Priority:** P1
- **Environment:** `https://demo.augastam.com/registration` / `https://demo-backend.augastam.com` (Build `2.0.66`)
- **Status:** Confirmed Code / Architecture Bug

---

## 1. Summary
In the NestJS backend (`patient-registration.controller.ts`), error conditions in `POST /patient-registration/create` and `PUT /patient-registration/update-details` do not throw HTTP exceptions; instead, they return plain JSON objects `{ statusCode: 409, message: '...' }` or `{ statusCode: 500, message: '...' }` inside an **HTTP 200/201** response. Meanwhile, the frontend API wrapper (`custom-form-builder/src/utils/api.js`) only checks `if (response?.data?.statusCode === 400)` in `createPatientRegistration` and checks nothing at all in `updatePatientRegistrationDetails`. Consequently, any `409` or `500` envelope returned by the backend is treated as a successful registration!

---

  if (conflicts.length > 0) {
    return {

- **File:** `akhil_systems_backend/src/patient-registration/patient-registration.controller.ts:3972-3975` (`update-details`)
  ```typescript
  return {
    statusCode: HttpStatus.INTERNAL_SERVER_ERROR, // 500 returned inside HTTP 200!

  ```

### B. Frontend Only Checks `statusCode === 400`
- **File:** `custom-form-builder/src/utils/api.js:2415-2441`

  // api.js:2416-2421
  const response = await api.post('/patient-registration/create', payload);

  ```
- **File:** `custom-form-builder/src/pages/registration/RegistrationPreview.jsx:3012-3043`

  const newId = created?.registrationId || created?.id || created?._id || created;
  // When `created` is `{ statusCode: 409, message: '...', conflicts: [...] }`,

  // and navigating to `/registration/<workflowId>/[object Object]`!
  ```

---

## 3. Recommended Fix
1. **Frontend (`custom-form-builder/src/utils/api.js:2416-2441`):**
   Check `if (response?.data?.statusCode >= 400)` in both `createPatientRegistration` and `updatePatientRegistrationDetails`:
   ```javascript
   if (response?.data?.statusCode >= 400) {
     const err = new Error(response.data.message || 'Patient registration request failed');
     err.response = { data: response.data, status: response.data.statusCode };
     throw err;
   }
   ```
2. **Backend (`patient-registration.controller.ts`):**
   Throw NestJS `HttpException` (`ConflictException`, `BadRequestException`, `InternalServerErrorException`) so the HTTP status code matches the payload's `statusCode`.
